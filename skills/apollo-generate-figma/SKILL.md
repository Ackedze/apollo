# Агентская генерация Figma в Apollo

Результат — созданный root в документе, проверяемый artifact и отчёт по
конкретному ScreenVersion. Если дан только промпт, используй общий planner
Apollo. Уточнение создаёт новую версию; внутри сборки версия неизменна.
Реальные действия Apollo в Figma и native-live приёмку запускает пользователь.
Изолированные проверки с synthetic PluginAPI сохраняются отдельно.

## Входы и сборка

Прочитай полный выбранный skill text, ScreenVersion, manual-контракты и
зависимости, RuleID links с полной нормой и semantic Figma mapping. Нормы бери
из manual; component keys/variants/properties/SLOT — из mapping и подтверждённых
источников. Source/API evidence не вводит новые нормы. Хеши не заменяют текст.

Используй текущий допущенный Apollo route/provider packet. Агент выбирает
последующие низкоуровневые шаги, читает ответы и исправляет результат. Прокси
связывает команду с запуском, runtime плагина выполняет её через PluginAPI.
Не вызывай renderer целого экрана или произвольный PluginAPI JavaScript.
Недоступный компонент/порт/variant возвращает named gap до зависимой записи.

UI и main должны подтвердить точный versionHash после сохранения Draft и
проверки существующим core. Получи актуальную привязку к документу/странице
через open. Используй run-local handles; отсутствующий fileKey не выдумывай.
Пиши в собственный новый root через разрешённые команды. Каждая запись требует
подтверждённого component/property/SLOT соответствия и актуальности запуска.
Текст меняется с фактическим шрифтом. Не используй имена слоёв вместо evidence.

Текущий ограниченный adapter profile описан в
[references/current-profile.md](references/current-profile.md). Прочитай его,
если packet использует interface-v7/MAP-02. Он описывает возможности адаптера,
а не универсальные нормы или разрешение на Ready. При другом профиле используй
его собственный текущий mapping/capabilities; ничего не переноси по аналогии.

## Проверка и исправление

Проверь условия ScreenSpec на фактическом дереве, а существующие исполняемые
правила — по RuleID при наличии нужных фактов. read_tree/check_scope дают
наблюдения, export_png — изображение. Pure checker сравнивает факты с точной
зафиксированной версией; агент дополнительно оценивает изображение/структуру.
Пометь визуальное суждение agent-review. Schema PASS и ответ модели не доказывают
native execution; неисполняемые нормы и непроверенное поведение остаются UNKNOWN.

Применимость checker проверяй для текущих компонентов, variants, состояний и
условий. Узкий checker пилота не универсален. При failed исправь собственный
результат разрешённой операцией, повтори readback и затронутые проверки. Не
меняй ScreenSpec, baseline библиотеки или нормы ради PASS. Если продолжение
невозможно, сохрани partial/blocked, созданную область и точную причину.

## Завершение и eval

Для сохранения требуются фактический readback, результат проверок и отдельное
подтверждение retain от runtime. При уточнении сохрани предыдущие успешные roots.
Ошибка, таймаут и отмена останавливают операции без автоматического удаления
созданного результата. Частичный root сохраняется как незавершённый Draft;
его наличие подтверждается отдельным native preservation receipt. Удаление
выполняет пользователь вручную в Figma. Чужое содержимое также сохраняется. Отсутствие ACK/receipt не означает
нулевые записи или успешное удаление. Поздний ответ не оживляет старый запуск.

Передай действующий target, ScreenVersion/source pins, readback/screenshot,
actual verdicts, agent-review и gaps. Разделяй candidate/working, source/API,
coverage, synthetic/native-live, Ready/release. Engineering Draft остаётся Draft.

При каждом проходе сохрани eval по [references/evals.md](references/evals.md).
Подтверждённую ошибку воспроизведи до правки скилла, затем проверь before/after и
затронутые прежние кейсы. Проблему runtime/source передай её владельцу; скилл не
получает право менять общий engine. Не автоматизируй изменение норм по одному
прогону и не расширяй область выполнения через learning.
