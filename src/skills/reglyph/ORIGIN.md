# ReGlyph в Apollo

Основа — предоставленный владельцем архив ReGlyph 0.1 Public Beta.
Сопоставлены исходники и готовая сборка архива; соответствия и правила защиты
перенесены без изменения содержания. Это не подтверждает ручную приёмку в Figma.

## Источники

- `dist/catalog.json`: `7c972d73d51775866922e73904b8545740539941769f36e36dc94f32be8be7ca`
- `dist/services-catalog.json`: `e9087b1ac59c26b3acf36844472e458885b46184dd7c4ab94b2202fb43b4982c`
- `data/detection/icon-containers.json`: `14a1afc5d9b3fb53f232c4abbd7b58e4a7797f2bd5440eb2cbfd944b5c8cabd1`

`default.json` и `services.json` семантически совпадают с входами.
`detection.json` дополнен 11 пресетами Android AlertViewV2: 7 наборов вариантов
и 4 отдельных компонента из секции `11782:17850`. Node ID вариантов сверены с Figma,
component key взяты из опубликованного каталога Android Views. Исходные 14 наборов
AlertView и 8 отдельных компонентов сохранены: всего защищены 33 пресета AlertView/V2.
`assets.js` содержит только используемые SVG интерфейса из архива:
`close`, `search`, `search-clear`, `arrow-right`, `bubble-tail`.
Брендовые растровые материалы, контакты и отдельный персонаж не включены.

## Интеграция

Навык «Перевести на Glyph-26» запускается из «Тулзы». Профиль ABM общий для
выбранных iOS/Android, без AB fallback. Смена канала/платформы сбрасывает план;
отдельной матрицы правил другого канала нет. Для Desktop/MobileWeb запуск запрещён.
Поиск и замена работают локально: Proxy compatibility preflight для навыка не нужен.
Общий журнал операций Apollo сохранён; доставка статистики не блокирует навык.
Специальные счётчики ReGlyph и формула экономии времени не добавлены.

Ядро работает через общий router Apollo, versioned RPC и проверку ревизий.
Object spread в main-коде заменён на `Object.assign` для совместимости с Figma.
Проверки контекста, принадлежности и состояния узлов повторяются перед записью.
Пакет ограничен границами Undo; ошибка замены восстанавливает исходный компонент.
Cmd/Ctrl+Z сбрасывает план и уведомляет зависимые инструменты Apollo.

Смена выделения/страницы после проверки вызывает подтверждение: «Остаться»
восстанавливает исходные объекты, «Проверить» сразу анализирует новое выделение.
Переход к найденной иконке не вызывает подтверждения. Устаревший рабочий список
скрывается; начало новой проверки очищает старые строки. Повторное уведомление
о том же выделении во время чтения не отменяет анализ. Реальное изменение
останавливает обход; до завершения текущего ограниченного по времени вызова
показано ожидание, затем доступна повторная проверка. Ошибки чтения не скрываются
уведомлением непустого выделения. Native-занятость сохраняется до конца запроса.

Сервисная замена выключена и в поставленном архиве, и в Apollo. При распознавании
проверенного заголовка «Сервисы» предлагается экран из «Уважаемые экраны».
Каталог сервисов остаётся в распознавании идентичности и исключений.

## Интерфейс и превью

Модалка выбора использует исходные 606 × 744 px, padding 32 px, радиус 48 px,
поиск 56 px и типографику ReGlyph с `keepWords`; маленькое окно адаптируется.
Стили изолированы через `apollo-reglyph-*`. Сохранены диалоги, поиск, категории,
ручной выбор, пропуски, частичный итог и повторная попытка оставшихся замен.
Поиск прокручивает варианты в начало; «Назад к замене» возвращает позицию списка.
Модалки и список используют исходные enter/exit-анимации, closing становится inert.
Размер окна не переключается; отдельной брендовой шапки ReGlyph нет.

Персонаж — общий `AuditMascot` Apollo без собственных ресурсов и обработчиков:
серый unchecked, зелёный clean, жёлтый warning, красный violation. Поиск и замена
включают checking; остальные состояния используют обычное моргание и взгляд
за курсором. Пауза анимаций и prefers-reduced-motion берутся из общего компонента.

Весь каталог PNG при ready не прогревается. Сканирование готовит исходники и
уникальные предложенные цели в общем пуле максимум из четырёх задач. `scan`
передаёт `targetPreviews` и `previewErrors` вместе со строками. Ошибка картинки
не убирает найденную иконку и не запрещает ручной выбор. Кэш общий с preview;
успешное большое превью восстанавливает маленькое и снимает его ошибку.

IntersectionObserver загружает видимые варианты выбора с rootMargin 100 px.
Подписки объединяются по ключу; закрытие/смена поиска снимает ненужную очередь
и повторы, выполняющийся native-вызов завершается. Видимые запросы получают
приоритет. Попытки учитываются при отправке, а не постановке/снятии очереди.
Новая проверка сбрасывает старую очередь превью и лимиты повторов.
Кэш изолирован ключами Apollo; очистка не запускает общий прогрев каталога.

## Проверки

Ревью Glyph-26 на iOS/Android читает эти же три JSON без отдельной копии каталога.
`icon-detection.js` содержит вынесенные из `engine.js` общие проверки защищённых
контекстов, валютного содержимого и контейнера иконки. Переход из ревью подготавливает план по ID принятого запуска через native-часть,
без повторного обхода всех экземпляров макета. Список иконок из UI не принимается;
исходные корни и ключи сверяются, проверки перед записью сохраняются.
Само ревью не вызывает замену. Успешные замены дополнительно передают `completedIds`
для удаления соответствующих карточек из ревью без повторного сканирования.
Регрессии ReGlyph проверяют сохранение поведения после извлечения; отдельные
`tests/v3-glyph26.test.js` проверяют классификацию и интеграцию с ревью, а
`tests/glyph26-ui.browser.cjs` — карточку «Иконки» и переходы на синтетических данных.

Regression-тесты покрывают bridge/client, каталог, native-защиты, отмену,
смену выделения, работу без Proxy, подготовку и восстановление превью.
Браузерный прогон использует собранный Apollo с синтетическими экземплярами
на 800/440 px. Ручная приёмка настоящих библиотечных экземпляров в Figma
проводится отдельно по `docs/OWNER_REGLYPH_TEST_CASES.md`.

## Замечания ревью и UI — 17.11.2026

Первое замечание (Undo) оставлено по прямому решению владельца, согласованному
с @Ackedze: обработчик продолжает вызывать обычный `figma.triggerUndo()`.
Команда не привязана исключительно к последнему подтверждённому пакету ReGlyph
и не погашается после отмены; до первой замены и при повторном нажатии она может
отменить предыдущую операцию Figma. Это известное сохранённое поведение,
а не исправленная проблема. Новые гарантии безопасности Undo не заявляются.

Второе замечание исправлено: «Остаться» больше не подавляет сведения о новом
выделении во время `setCurrentPageAsync()`. Сохраняются исходная/целевая страницы
и их выделение; собственное событие перехода отделяется от последующего выбора
пользователя. После `await` повторно сверяются страница и выделение, даже если
событие ещё не пришло. При новом выборе старое выделение не присваивается.
Создаётся подтверждение с новым токеном (`changed-during-restore`); старый ответ
не может примениться. Видимые заголовок и текст остаются прежними:
«Проверить другой макет?» / «Текущую проверку мне придётся сбросить.».
«Проверить» сканирует текущий выбор, «Остаться» повторяет возврат. Если нового
выбора нет, исходное выделение восстанавливается без дополнительной модалки.

Регрессии покрывают новый фрейм, переход на третью страницу, запоздавшее событие,
обычный возврат без ложного подтверждения и оба действия повторной модалки.
Браузерный сценарий использует задержанный переход страницы через native bridge.

Группа «Этих иконок нет в Glyph 26» располагается сразу после «Этих иконок нет
в библиотеках», до остальных групп, включая логотипы и готовые замены.
Исходные карточки без соответствия подсвечены жёлтым (#fdf9ec); оформление
целевых карточек сохраняется. В шапках выделена колонка 48 px для кнопки закрытия
с центрированным SVG 24 px. Основное окно и вложенные модалки имеют отступы
шапки 32 px сверху и по бокам, на ширине до 500 px — 24 px. Изменения CSS
ограничены ReGlyph, общий AuditMascot и остальные инструменты не менялись.
