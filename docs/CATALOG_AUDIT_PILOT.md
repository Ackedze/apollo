# Каталожный пилот TitleView

Настройка **«Подключить каталоги»** выбирает источник независимого эталона.
По умолчанию она выключена; во время проверки переключатель недоступен.

| Режим | Источник |
| --- | --- |
| Выключен | Прежний захват библиотечного эталона |
| Включён | Существующий Athena raw из установленного пакета данных Proxy |

## Данные и чтение

Источник — существующие `structure` и `variantStructures`. Proxy переиспользует
V3 `resolveStructure`: выбирает опубликованный вариант по ключу и применяет его
patches. В ответе находится только выбранное дерево, pin исходного raw и карта
variant key → component set key из зарегистрированных raw-каталогов.
Отдельный файл снимка или блок `nativeAuditFactsV1` не требуется.

В пилот включены TitleView Desktop/MobileWeb и 11 существующих зависимостей:
Button, Spinner, Status & Property, Status, StatusBadge, IconView, Indicator,
Link, FilterCompanySelect, IconButton и Skeleton. Служебные части проверяются
по эталону и правилам владельца; самостоятельный контракт подключается там,
где он уже существует. Нормы, manual, compiled contracts и ревизии не меняются.

Apollo читает фактическую область без создания страниц, временных экземпляров
и импорта библиотечных ресурсов. Raw превращается во внутренние факты в памяти.
Style/token ID разных документов сопоставляются только по подтверждённым
библиотечным ключам. Наблюдаемые значения не копируются в эталон.

## Сопоставление и правила

Корень должен совпасть по опубликованному ключу и семейству. Вложенные узлы
сопоставляются внутри подтверждённой цепочки родителей; первый одноимённый узел
или порядковый номер не доказывает соответствие. Неоднозначность остаётся UNKNOWN.

Изменённый вариант того же семейства позволяет прочитать его фактическую VARIANT
настройку для правила применения. Старый визуальный baseline его потомков
не переносится. Для нескольких одинаковых вложений существующий source address
контракта и наблюдаемый ID экземпляра могут подтвердить конкретную настройку;
они не выбирают произвольный raw baseline среди одинаковых соседей.

Проверки соответствия Status/TitleStatus, запрета Accent на Desktop и типографики
вложенной Button исполняются независимо. Недоступный факт одной проверки не
отменяет остальные. Ранее вычисленные привязки и признаки неактивных зависимостей
пересчитываются; при потере соответствия они не переиспользуются.

Проверки, явно требующие native source continuity, не получают такую гарантию
из raw. Отсутствующие Auto Layout alignment/sizing, explicit instance modes,
mixed-text ranges и public BOOLEAN/SWAP wiring не выдумываются. UNKNOWN относится
к потребляющему условию. Первые два пробела записаны в backlog; новых выгрузок
этот этап не требует.

## Подготовка и совместимость

Нужны совместимые reader Apollo и Proxy, raw descriptors в индексе данных и
закреплённые исходные raw. Сборщик пакета включает эти файлы из DS и проверяет
их pins. Push исходников не обновляет установленное приложение или данные.

Consumer проверяет release ID, запрос, контракт/revision/manual hash,
representation, variant, хеш ответа и топологию. Ошибка каталога не включает
скрытый live fallback и не означает потерю соединения. Stop и freshness guards
сохранены; финальная перепроверка использует тот же источник.

В отчёте `referenceMechanism` различает `catalog-pilot` и `live-library`.
`catalogReference.mechanism=athena-v3-raw-catalogue` и raw provenance различают новый
reader; сохраняются `referenceHash` и `releaseId`. Переключение режима помечает
предыдущий контрактный результат устаревшим.

Локальная реализация Apollo 0.4.5 проверена автоматически и на сохранённом отчёте.
Это не свежая приёмка Figma и не публикация. Для сравнения OFF/ON владелец запускает
одну область с одинаковыми данными и настройками и сохраняет оба JSON, время
первого/повторного запуска, нарушения и UNKNOWN. Установку и ручные тесты
выполняет владелец; плагин он публикует самостоятельно.
