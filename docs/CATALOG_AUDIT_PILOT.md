# Каталожный пилот проверки

Настройка **«Подключить каталоги»** сравнивает два источника независимого эталона
в одной сборке Apollo. По умолчанию она выключена; значение сохраняется
в обычных настройках плагина. Во время проверки переключатель недоступен.

| Режим | Источник эталона |
| --- | --- |
| Выключен | Действующий захват библиотечного экземпляра |
| Включён | Athena raw-каталог из подключённого пакета данных Proxy |

Каталожный режим пока ограничен Core Button Desktop, TitleView Desktop/MobileWeb и
зависимостью Spinner. Поддерживаются только явно выгруженные варианты и
подтверждённые исходные конфигурации. Другие компоненты и отсутствующие
конфигурации получают явное неполное покрытие. Скрытого возврата к созданию
библиотечных экземпляров в этом режиме нет.

Опубликованный первый пакет содержит восемь вариантов TitleView Desktop. Для
Button/Spinner исходные деревья прочитаны, но получение части метаданных
ресурсов из Core-файла отклонено readonly-инструментом; эти каталоги не объявлены
готовыми и в пакет пока не включены. У TitleView сохранены прежние пробелы
контракта для Skeleton и mixed fill xLarge; новые UNKNOWN не скрываются.

Следующая локальная подготовка включает все 16 TitleView-вариантов: Desktop и
MobileWeb, четыре View, Skeleton False/True. Оба представления уже находились
в исходном `Web _ Corp Components -- TitleView.json`; отсутствовало их подключение
с нативными фактами в пакете пилота, а не MobileWeb raw. Исходник сохранён;
дополненный каталог и единый набор находятся в DS `TitleView/pilot/`.
Полевая приёмка и публикация этого дополнения ещё не выполнены.

Прямой BOOLEAN→visible теперь конфигурируется из независимой исходной привязки:
тип, единственность свойства, bindings/references, source owner и начальное
visible должны быть доказаны. Сложные и неизвестные связи отклоняются.
После переключения геометрия, зависящая от reflow, остаётся UNKNOWN. Нормы,
Predicate Engine и проверяемые факты не исключаются. Автоматические контроли
охватывают 3072 BOOLEAN-комбинации и 42 отрицательных условия на каждой платформе;
они не заменяют сравнение нативных результатов OFF/ON владельцем.

Единый набор содержит все нормы r4, профили и разрешённые API-состояния.
Skeleton-профили сохраняют 19–21 human-review, а xLarge — один mixed-paint
human-review. Эти пробелы не объявлены успешно проверенными состояниями.

Полевой прогон 03.11.2026 показал, что предложенный TV-03 не является
исходной конфигурацией: в экземпляре `Holding=False`, в каталоге `Holding=True`.
Результат `CATALOG_CONFIGURATION_UNSUPPORTED` означает отсутствие контрактной
проверки; его короткое время нельзя считать ускорением.

Локальное исправление разрешает изменение типизированного BOOLEAN/TEXT только
если полная исходная топология, включая скрытые узлы, доказывает отсутствие
связей с этим свойством. Для TV-03 это `Holding`. Режим шрифта выбирает значения
из независимых `valuesByMode`, включая цепочку alias. Для System (SF) дополнены
две отсутствовавшие переменные tracking из библиотеки и список доступных пар
family/style. Наблюдаемые свойства макета не подставляются в эталон. Геометрия,
зависящая от новых метрик шрифта, остаётся UNKNOWN; она не вычисляется из одного
названия шрифта. Остальные конфигурации без достаточных данных по-прежнему
отклоняются. Поддержка всех вариантов System (SF) не заявляется.

Повторное выполнение сохранённого TV-03 с исправлением даёт те же 138 оценок:
115 compliant, 23 not-applicable. Совпадают полные trace, actual/expected и пути
фактов. Контрольное изменение opacity обнаруживается как нарушение. Это
автоматический replay, а не новый полевой замер скорости Figma.

Следующий полевой прогон обнаружил отказ выбора режима Theme: экспорт содержит
два локальных ID с одним библиотечным ключом. Индексация режимов теперь использует
точный `modeCatalog.collectionId`, а не все записи с совпадающим ключом. Лишняя
запись ресурсов без использующих её фактов не становится вторым контекстом режима.
Неоднозначность действительно используемых коллекций по-прежнему отклоняется.
Регрессия воспроизводит native-сопоставление по ключу: девять исходных ID коллекций
соответствуют восьми коллекциям документа; полный replay снова даёт те же 138
оценок и trace. Быстрый отказ с нулём оценок не считается успешной проверкой.

В общем планировщике чтения сохранён бюджет 8 мс и добавлен обмен сообщениями
main → UI → main для передачи управления хосту. Прежний таймер остаётся запасным
путём; первый завершившийся путь снимает ожидание. Stop и проверки актуальности
сохраняются. Влияние на время реальной проверки ещё должен измерить владелец.

Ответ Proxy с постоянной ошибкой `CATALOG_*`, включая HTTP 503 при отсутствии
закреплённого каталога, передаётся в результат как явный пробел покрытия.
Он не означает потерю соединения и не запускает бесконечное повторение запроса.

## Что переиспользовано

- Из V3: сборка дерева из base structure и patches выбранного варианта;
  нормализация каталожных полей и порядок patch-операций.
- Из текущего Apollo: чтение фактического дерева, контракты, Predicate Engine,
  материализация независимого baseline, зависимости, Stop, контроль изменения
  области и финальная перепроверка.
- Из Proxy: установленный immutable data root, индекс контрактов и проверка
  хешей. Новый маршрут `POST /v2/contracts/catalog-resolve` возвращает один
  выбранный эталон; модель и Figma MCP при обычной проверке не вызываются.

Raw-каталог хранится один раз. Полные деревья всех вариантов в плагин
не передаются и отдельные постоянные файлы проекций не требуются.

## Необходимые данные

Обычного старого raw недостаточно: ему недостаёт части нативных фактов и
исходных идентификаторов узлов. Пилот использует дополнительное поле
`nativeAuditFactsV1` в том же дереве/patch-формате. Оно снимается с существующих
библиотечных master-компонентов без создания экземпляров. Обход обязан включать
детей невидимых экземпляров; `skipInvisibleInstanceChildren=true` не доказывает
полноту дерева.

Consumer проверяет контракт, revision, representation, variant, хеш ответа,
полноту топологии и необходимые правилам факты. Локальные ID стилей, переменных,
коллекций и компонентов сопоставляются по доказанным библиотечным ключам.
Наблюдаемые визуальные значения не копируются в эталон. Отсутствующая у
фактического слоя привязка остаётся проверяемым отличием, а ошибка чтения
ресурса сохраняет непроверенное покрытие.

Каталог без настроенного независимого host-эталона для swap или смены вложенного
варианта не закрывает соответствующую проверку. Нормы контрактов и UNKNOWN
политика не смягчаются.

## Совместимость и сравнение

Для включённого режима нужны одновременно новая локальная сборка Apollo,
Proxy с маршрутом `catalog-resolve` и пакет с `rawCatalogs` в индексе контрактов.
Отсутствующий маршрут просит обновить Proxy; отсутствующий каталог остаётся
отдельной ошибкой данных. Выключенный режим использует прежний API.

В выгрузке результата `referenceMechanism` различает `catalog-pilot` и
`live-library`, а у проверенных компонентов есть `referenceOrigin`.
У каталожного snapshot сохраняются `referenceHash` и `releaseId`.
Сравнивать следует одинаковые область, настройки и данные: время capture,
финальной перепроверки, число исполненных правил и UNKNOWN. Само переключение
режима помечает прежний контрактный результат устаревшим.

Установку и ручные прогоны выполняет владелец. Подготовка локальной сборки
не публикует плагин, миниапп или пакет данных.

## Исправление сложного TitleView, 03.11.2026

Семантические ссылки ресурсов собираются из фактов узлов, включая смешанный текст
и цепочки переменных. Копии baseline, traces и каталоги режимов не расходуют
бюджет UI-подписей. Проверки native key, отсутствующих ресурсов и неоднозначности
сохранены; импорт ресурсов и переход в live-режим не добавлены.

TitleView r5 включает существующий `instanceMainComponentAliasesVersion=1`:
локальные ID одного опубликованного компонента сопоставляются только при
совпадении key/set, точного source occurrence и владельца. На сохранённом сложном
кейсе это восстанавливает106/130 baseline и план трёх независимых вложенных
эталонов. Остальные24 узла старого отчёта не дорисовываются. Свежий native прогон
выполняет владелец. Неподдержанное каталожное вложенное состояние остаётся UNKNOWN.

Публичные Type/View и effective visibility в r5 читаются через versioned
`nativeTargetUsageFactsVersion=1` только после native source proof и совпадения
семейства. Корневые usage-правила не требуют присваивать изменённой вложенной
вариации visual target role. Portable swap pins нормализуют только подтверждённые
local component IDs в library keys; чужая identity, missing key closure и
реальная смена API продолжают давать UNKNOWN. Proxy1.4.17 нужен для нового
runtime; установленное приложение и ручной тест не меняются агентом.
