# ReGlyph: ручная приёмка в Apollo

Дата подготовки: 29.10.2026. Проверяется навык **«Обновить иконки»**: выбор замен, превью и работа с результатом для ранее проверенного фрейма. Прогон выполняет владелец на копии макета.

## Перед началом

Обновление Proxy и знаний само по себе не обновляет открытый UI плагина Figma.

**Подтверждённое состояние поставки:** владелец подтвердил успешное повторное обновление приложения. General проверил фактически запущенный Proxy `1.4.4 / 2026102901` и данные `764eee…`, 41 контракт. Блокер отсутствия совместимого Proxy для доставленных проверок паттернов wave2 снят. Это ещё не приёмка Figma/model-кейсов и не подтверждение свежего UI Apollo. Сборка `2026102902` остаётся локальной и для этой приёмки не требуется. ReGlyph работает независимо от Proxy.

Окно «О прокси» показывает версию приложения без отдельного номера build; `2026102901` уже подтверждён General, искать его через терминал не нужно. В «Знаниях» сверяется начало версии содержимого; имя пакета приведено для справки.

Повторный системный запрос пароля macOS относился к Keychain. Корпоративная активация Apollo от 28.10.2026 сохранена; повторять её для этого прогона не требуется.

Для свежего UI закрой Apollo и открой его заново через **Figma → Plugins → Development → Apollo**. Development-плагин должен быть подключён к `/Users/alexkukhta/Desktop/workplace/projects/Apollo/manifest.json`. Если он зарегистрирован из другой папки, выбери **Import plugin from manifest…** и укажи этот файл. Затем сверь строку сборки. Если она другая, приложи её скриншот: прохождение кейса на старом UI не подтверждает приёмку этой версии.

ReGlyph работает локально, **без ИИ и Proxy**. Версии Proxy/знаний выше обозначают общую поставку; их наличие не доказывает обновление ReGlyph. Для самого навыка нужны свежий UI Apollo и доступ к исходной библиотеке иконок. Вход в модель для этих кейсов не требуется. Не нужно добиваться ровно 41 строки в таблице «Данные Apollo»: это число контрактов пакета, а не обещанное число строк этого окна.

В шапке Apollo выбери **iOS** в группе **ABM**; в настройках оставь канал **b2b**. Перейди **«Навыки» → «Обновить иконки»**, внизу выбери **«Базовая замена»**.

## Подготовка двух фреймов

Постоянного Figma-фрейма для этого сценария нет: сохранённые автоматические кейсы используют искусственные экземпляры. Для ручного теста подготовь следующие реальные экземпляры на копии страницы:

1. Создай фрейм `RG-A` примерно 360 × 160. Помести прямо внутрь два библиотечных **instance**, без detach и защищённых компонентных обёрток:
   - [a-scores-circle / Size=m — старая иконка](https://www.figma.com/design/ZcdUPebEhHfSZ91zgmv2cK/Icons?node-id=19574-1191);
   - [calendar / Size=m — старая иконка](https://www.figma.com/design/ZcdUPebEhHfSZ91zgmv2cK/Icons?node-id=17931-1225).
2. Оставь обе иконки видимыми, размером 24 × 24; размести рядом, без наложения. Переноси их как связанные экземпляры, а не картинку, векторы или копию определения компонента.
3. Дублируй фрейм как `RG-B`. Оставь ещё одну нетронутую копию `RG-Эталон` для восстановления перед негативными кейсами. Сделай скриншот исходного состояния.

В базовом каталоге этим исходникам соответствуют новые `a-scores-circle` и `calendar` из Glyph 26 с параметрами `Size=24, Style=Line, Color=False`. Проверяй реальный компонент через панель Figma и переход к основному компоненту: внешне старая и новая версии могут быть похожи.

Если старые компоненты недоступны или скопировались без библиотечной связи, отметь **UNKNOWN — нет подходящего исходника/доступа**. Не заменяй их произвольными похожими иконками и не считай пустой результат дефектом обнаружения.

## Обязательный smoke: выполнить по порядку

### RG-S01 — проверка ничего не меняет

**Подготовка:** исходные `RG-A` и `RG-B`. Выделен только `RG-A`.

**Шаги:** открой навык и нажми **«Проверить иконки»**. Дождись списка соответствий.

**Ожидается:** строка **«Проверенная область: RG-A»**, исходные и предлагаемые иконки; обе области пока сохраняют старые компоненты. Для этой чистой заготовки ожидаются предложения для двух добавленных экземпляров. На произвольном рабочем экране количество может отличаться.

**Дефект:** компонент заменился до нажатия «Заменить», результат относится к другой области или известные связанные исходники не обнаружены. **UNKNOWN:** не подтверждены библиотечные связи либо показана ошибка чтения/доступа к библиотеке.

### RG-S02 — ручное соответствие и сохранение результата

**Подготовка:** результат RG-S01.

**Шаги:** у `a-scores-circle` нажми **«Выбрать»**. В окне **«Выбери иконку из Glyph 26»** введи `calendar`, выбери `calendar`. Это намеренная тестовая замена только на копии. Закрой окно навыка крестиком. Выдели `RG-B`, снова открой **«Обновить иконки»**.

**Ожидается:** прежние строки и ручной выбор сохранены; область по-прежнему `RG-A`. Нет ошибки о смене выделения и требования заново проверять макет. Кнопка применения доступна после завершения фоновых операций.

**Дефект:** список/выбор потерялся, область переключилась на `RG-B` или замена блокируется только из-за нового выделения. **UNKNOWN:** иконка недоступна в библиотеке; отдельная ошибка превью ещё не доказывает потерю результата.

### RG-S03 — превью и «Показать в макете» относятся к RG-A

**Подготовка:** результат RG-S02, выделен `RG-B`.

**Шаги:** нажми на миниатюру исходной и предлагаемой иконки, поочерёдно закрой увеличенные превью. Нажми **«Показать в макете»** у исходной строки. Затем снова выдели `RG-B`.

**Ожидается:** превью можно открыть и закрыть; Figma выделяет и показывает исходную иконку **в RG-A**. После повторного выбора `RG-B` результат и действия остаются доступны.

**Дефект:** переход ведёт к экземпляру из `RG-B`, не работает при неизменном исходнике или закрывает/стирает результат. **UNKNOWN:** превью недоступно, а доступ к библиотечному исходнику не подтверждён; сохрани текст ошибки и отдельно проверь переход к слою.

### RG-S04 — частичная замена меняет только исходную область

**Подготовка:** тот же результат, выделен `RG-B`.

**Шаги:** у исходного `calendar` нажми **«Выбрать» → «Пропустить»**. Нажми **«Заменить · …»**. В окне **«Точно заменяем?»** подтверди замену.

**Ожидается:** до подтверждения изменений нет. После него выбранная строка заменена в `RG-A`, пропущенная остаётся старой. `RG-B` полностью сохраняет исходные компоненты. Итог показывает заменённые, пропущенные и неудавшиеся вхождения; для этой заготовки — одна замена и один пропуск при отсутствии ошибок. Размер, положение и исходный цвет заменённой иконки сохраняются.

**Дефект:** изменился `RG-B`, заменена пропущенная строка, выполнена замена до подтверждения либо сломаны размер/цвет/раскладка. **UNKNOWN:** явный отказ импорта целевого компонента или недоступная переменная цвета; это незавершённый кейс, а не PASS.

### RG-S05 — остаток работает без пересканирования; новая проверка выбирает новую область

**Подготовка:** итог RG-S04, `RG-B` остаётся выделенным.

**Шаги:** нажми **«Назад к замене»**, для оставшейся строки выбери `calendar` и примени замену. После итога нажми **«Новая проверка»**, затем **«Проверить иконки»**, не меняя выделение `RG-B`.

**Ожидается:** остаток сначала заменяется в `RG-A` без повторного сканирования; `RG-B` в этот момент ещё нетронут. Только явная новая проверка показывает **«Проверенная область: RG-B»** и его старые иконки. Само новое сканирование их не заменяет.

**Дефект:** для остатка требуется новая проверка, повторно меняются уже обработанные иконки или новая проверка продолжает использовать `RG-A`. **UNKNOWN:** библиотечная ошибка, не позволяющая завершить применение или прочитать исходники.

## Как трактовать ограничения

- Пройденные автоматические кейсы подтверждают логику на искусственных экземплярах и UI на 800/440 px. Они не подтверждают доступ к настоящим библиотекам, качество всех соответствий или прохождение этой ручной приёмки.
- Сейчас доступность ReGlyph определяется **iOS/Android**; обе платформы используют общую матрицу АБМ. Смена канала сбрасывает план, но **не переключает матрицу**. При iOS/Android другой канал также не блокирует запуск. Это известная граница текущей реализации, а не доказательство поддержки АБ или других каналов.
- Для проверки качества сценария «Замена в сервисах» нужен настоящий экран сервисов с распознаваемыми карточками и заголовками. Простой `RG-A` проверяет только переключение сценария/подтверждение; неподтверждённую сервисную матрицу отметь UNKNOWN.
- «Дождись завершения другой операции Apollo» — блокировка на время другой операции, а не ошибка смены выделения. Повтори действие после её завершения.
- После реального изменения источника допустимы явный отказ и новая проверка. После обычного выбора другого объекта требование новой проверки — дефект.
- UNKNOWN означает, что не хватает проверяемого исходника или подтверждённого доступа. Если корректные экземпляры и доступ подтверждены, воспроизводимую ошибку чтения, превью или импорта запиши как DEFECT, а не UNKNOWN.

## Обратная связь

Достаточно сначала пройти RG-S01–RG-S05. Затем — негативные кейсы, смена контекста и узкое окно. Для каждого результата используй:

```text
Кейс: RG-S04
Статус: PASS / DEFECT / UNKNOWN
Apollo: версия и сборка из настроек
Платформа / канал / сценарий:
Ссылка на копию макета и проверенный фрейм:
Что сделал:
Ожидал:
Получил: включая точный текст ошибки и числа из итога
Изменился ли RG-B:
Вложение: скриншот результата и исходного/нового компонента в Figma
```

У ReGlyph нет отдельной кнопки экспорта отчёта: приложи скриншот списка или итога. Если вместе с кейсом сохранён отчёт общей проверки Apollo, можно приложить его экспорт дополнительно; он не заменяет проверку того, какой именно фрейм и компонент изменились.
