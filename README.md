# Apollo

Локальный кандидат **0.4.16** переводит генерацию на прямой Codex CLI → Figma MCP.
Нужен совместимый Proxy и пакет навыка лендингов0.6.0; старый flow не возобновляется.
Установка, публикация и ручная приёмка не выполнены этой правкой.

Версия исходников указана в [package.json](package.json), ID загруженной сборки — в настройках и консоли плагина. Основная ветка и локальная сборка могут опережать опубликованную версию. Плагин публикует владелец; установку и ручную проверку в Figma выполняет он сам.

## Активная проверка V3

Проверка компонентов и текстов использует перенесённые сборщик, сравнение и специализированные правила Apollo V3 в текущем интерфейсе. Контрактный пилот V4 остановлен; его ядро и fallback не входят в этот маршрут. Генерация, «Спросить» и «Тулзы» сохраняют отдельные исполнители.

Итоговая оценка находки формируется один раз в V3 после сравнения, контекстных правил и разрешённых настроек. Карточки, счётчики, JSON и статистика используют эту оценку; экспорт не дооценивает UNKNOWN самостоятельно. Названия `component-contract` в правилах и метаданных унаследованы от V3 и не включают контрактный движок V4.

Native-область задаётся выделением, а при пустом выделении — текущей страницей. Точки входа: [native-port.ts](src/v3-audit/native-port.ts), [entry.ts](src/v3-audit/entry.ts) и [ui-client.js](src/v3-audit/ui-client.js). Каталоги и подготовленные правила поступают только из установленного пакета Proxy через `/v1/audit-data/manifest` и `/v1/audit-data/:dataId/assets/:fileId`. Прямого чтения Git при проверке нет. Проверяются точные UTF-8 длины, SHA и dataId; после смены набора требуется закрыть и заново открыть Apollo.

Нарушения, допустимые настройки и непроверенные факты различаются. Подтверждённое нарушение не скрывает неполное покрытие других фактов. Все отличия от эталона показаны отдельно и не удваивают счётчики. Старый результат остаётся видимым до принятия нового; устаревшие действия недоступны. Исправления используют сохранённые native-действия и исходные слои, проверяют актуальность перед записью и затем перепроверяют исходную область.

Проверка текстов передаёт исходный V3 text-report в POST/GET `/v1/analyze/codex/runs`. Stop прекращает клиентское ожидание и отбрасывает поздний ответ; серверная задача может продолжаться. В блоке «Диагностика проверки» можно скачать JSON компонентов или текстов с исходным payload, runId/dataId/settings и отдельными pending/stale/error признаками. Снимок без принятого результата имеет статус diagnostic и не выдаётся за завершённую проверку.

Диагностический JSON также сохраняет техническую цепочку последних четырёх запросов каждого вида проверки: до 64 событий UI и native на запрос, первый отказ и число вытесненных событий. Это позволяет различить изменение макета, отсутствие доказательств актуальности, отказ чтения данных и остановку. Трейсер использует существующие уведомления и ответы, не запрашивает дополнительные свойства Figma и не меняет условия проверки.

Во вкладке «Кастомы» видны подтверждённые нарушения и у компонентов из «Пора менять» и «Устаревшие». Точные дубли дополнительных находок удаляются; разные правила, привязки и доказательства сохраняются. «Локальные» показывает компоненты вне подключённых каталогов DS, независимо от `remote` в Figma; недоступная или неоднозначная идентификация остаётся непроверенной. Градиенты учитываются общей проверкой стилей, а отвязанные значения находятся во вкладке «Без стиля или токена».

## Другие функции и сохранённые адаптеры

В генерации выбор навыка и «Настройки экрана» имеют одинаковое округлое оформление. История чатов расположена слева, оформлена как шильдик Proxy в «Спросить» и открывает меню от своего левого края. Автоматические UI-проверки используют реальный legacy-каскад на фиксированной ширине 800 px.

Профиль лендингов `ab-generate-custom-landing` 0.5.0 использует порядок
«каркас → подтверждение структуры → наполнение». Агент готовит план по DS AI HUB,
а общий исполнитель плагина размещает контейнеры, библиотечные экземпляры и
публичные слоты. До подтверждения структуры агент с правом записи не запускается.
Структуру можно показать в Figma, изменить и подтвердить заново. После Stop
продолжение сохраняет созданные узлы и их ID. Нужны совместимые новые плагин,
Proxy и пакет навыка; старый клиент получает отказ совместимости до записи.

В проверке по навыку `ab-audit-figma` недоступность отдельных метаданных компонента отмечается по полям и не подменяется данными родительского набора. При ошибке чтения сохраняются ограниченная native-диагностика и подтверждённый ответ остановки с уже собранными планом и доказательствами. Исходное исключение прежнего прогона без этой диагностики задним числом не восстанавливается.

Генерация повторяет недоставленные подтверждения Proxy с тем же идентификатором
операции после сверки свежего снимка. Временная потеря связи сохраняет native lease;
новая запись в Figma при таком повторе не запускается. Старые Proxy поддержаны
через согласование sequence. Подробности: [протокол лендингов](docs/LANDING.md).

Native evidence v2 передаёт полный снимок до 2 МиБ и независимые default modes.
Продолжение использует сохранённый план и тот же root; несовместимый протокол
останавливается до создания области.


Прежний [контрактный каталожный пилот](docs/CATALOG_AUDIT_PILOT.md) сохранён
как исторический материал. Его переключатель и контрактная компиляция не
используются активной проверкой V3; сохранённые адаптеры не являются её fallback.
Статистика проверяет SHA-256 квитанции по хешу точной сохранённой записи,
вычисленному существующим core в main sandbox; `crypto.subtle` iframe не требуется.
Подтверждённые записи отправляются до сохранения новых, чтобы освободить очередь.
При недоступном Proxy записи сохраняются, повторы идут с паузой; Native progress
продлевает только watchdog соответствующего запроса. Начальный лог `[Apollo] build`
показывает точный ID загруженной сборки для различения published/development.

Apollo проверяет совместимость при подключении к Proxy и перед новой проверкой,
вопросом, генерацией или запуском тулзы. `/health` сообщает версию программы и
метаданные фактически подключённых данных. При несовместимости плагин отдельно
просит обновить Proxy, знания или сам Apollo; зелёный индикатор означает
подтверждённую совместимость. «Проверить снова» повторяет проверку без перезагрузки.
Сохранённые результаты и текст запроса остаются на месте. Stop и текущие операции
не прерываются повторной проверкой версий.

Точные минимумы Proxy, профиля и даты пакета заданы в
[compatibility-requirements.json](src/compatibility-requirements.json).
Они обновляются вместе с функцией, требующей нового кода или данных.
Более новые совместимые пакеты допускаются без пересборки Apollo. Минимумы
нужно менять, когда новая функция требует другого API или данных.
Старые сборки Proxy без handshake просят обновить программу: `/health.ok=true`
сам по себе не подтверждает совместимость. Для этой функции нужен отдельный
выпуск Proxy с метаданными; новый пакет данных не требуется, если уже установлен
принятый выпуск или новее. Metadata не заменяет source/hash/coverage guards.

Компиляция служебного списка `capabilities.facts` использует одинаковую
сортировку в Node и runtime плагина. Неизменный контракт сохраняет свой
закреплённый хеш; изменённый manual или факты по-прежнему отклоняются.

Проверка «Стили и токены → Устаревшие» разрешает применённый `styleId` через
Figma в библиотечный `key` и сверяет его с версионированным индексом из пакета
знаний Proxy. Проверяются заливки, обводки, эффекты и участки текста видимых
слоёв. Карточка показывает стиль и переход к слою. Совпадение названия не
является основанием для нарушения. Отсутствующий индекс, недоступный ресурс
или противоречащие каталоги сохраняют неполное покрытие / UNKNOWN.
Для первого подключения нужны новая сборка Apollo, Proxy с
`GET /v1/style-token-catalog/deprecated-styles` и новый пакет данных;
последующие изменения списка устаревания поставляются через данные.
Устаревание токенов пока не объявляется: отдельный список для них не задан.

Основной плагин Figma: [manifest.json](manifest.json), ID публикации **1616850453760090547**. Приложение находится непосредственно в корне репозитория.

Исправление от 01.11.2026 для границ Slot/swap и эталонов вложенных компонентов
требует перезапуска плагина с новой локальной сборкой и обновления пакета данных
Proxy. Произвольное содержимое разрешённой границы остаётся непроверенным, пока
для него нет собственного контракта; известные дочерние контракты исполняются.

## Что делает Apollo

| Раздел | Возможности |
| --- | --- |
| Дизайн | Собирает факты Figma, проверяет стили/компоненты/контракты, показывает нарушения и покрытие |
| Спросить | Отправляет вопрос и историю выбранному в Proxy агенту |
| Генерация | Лендинг Альфа-Бизнеса: бриф, уточнения, редактируемый макет через Figma MCP и правки секций |
| Тулзы | Отдельные сценарии, включая предложения по названиям слоёв и выбранные переименования |
| Данные Apollo | Версии контрактов и подключение проверки/Figma/frontend по метаданным Proxy |

Обычная проверка и окно данных не вызывают модель. Агентские действия выполняются
отдельно через Proxy. Проверка компонента и его генерация требуют разных данных
и mapping; текущую поставку сверяйте через API и окно данных. Новый сценарий лендингов
описан в [LANDING.md](docs/LANDING.md). Прежние исполнители генерации, включая frontend, отключены;
общие контракты и frontend mappings сохраняются для чтения данных.

## Быстрый старт разработчика

```sh
npm ci
npm run validate
```

Импортируй корневой manifest в Figma. Сборка создаёт `dist/code.js`, `dist/ui.html` и серверный `dist/runtime.cjs`.
Полный validate использует соседний checkout Proxy; структура всех четырёх
репозиториев и настройки — в [общем старте](docs/AGENT_START_PROMPT.md).

## Код, данные и совместимость

Коллекция ZIP выбирается только её `manifest.json`. При `archivePathBase: "design-system_ab"`
пути указывают на `JSONS/web/components/.../packages` относительно корня DS;
manual/facts выбирает существующий source index. Legacy коллекции и входящие
каталоги ZIP сохраняют прежнюю базу путей. Basename, SHA, canonical source
projection и stale/symlink guards проверяются до использования; history рекурсивно
не подбирается. Дата изменения берётся из `metadata.updatedAt` manual, а точная
версия — из revision и hashes.

- `src/` — проверка макетов, интерфейс и генерация.
- `packages/` — общий ComponentContract Core, Pattern Core и совместимые форматы данных.
- `scripts/`, `tests/` — сборка, проверки и инструменты.
- Apollo Proxy расположен в `services/apollo-proxy` workspace и выбирает этот checkout через `APOLLO_PROJECT_ROOT`.
- Контракты и история Proxy хранятся отдельно от кода. Подключение mapping не повышает Draft до Ready.

При проверке контрактов выбранная настройка «Платформа» передаётся как явный
`ViewportClass`, если контракт объявляет такой вход. Она не меняет платформу
захваченного компонента; несовпадение Desktop/MobileWeb остаётся нарушением.
Диагностика свойств зависимостей показывает имя свойства и компонента вместо
служебного пути; исходный trace сохраняется в отчёте.

[Правила переноса и совместимость](MIGRATION.md) · [Архитектурный бэклог](docs/ARCHITECTURE_BACKLOG.md) · [История разработки](docs/DEVELOPMENT_HISTORY.md)

Команды сборки не публикуют плагин и не выполняют push. Проверки и вопросы сохраняются; генерация лендингов использует новый диалог.

«Спросить» использует агента, выбранного в окне «О прокси»: Codex, Claude или корпоративный AlfaGen.
Ответ показывает фактический агент, возвращённый Proxy. AlfaGen использует настроенный HTTP-адрес;
версия его удалённой базы знаний не подменяется версией локального пакета. AI-проверки, навыки и генерация
через AlfaGen пока не поддержаны; для них выберите Codex или Claude.
Старая скрытая настройка чата Langflow автоматически переводится на локальный маршрут
при открытии плагина. История текущего диалога и сессия сохраняются; отдельный
HTTP API Langflow остаётся доступен для клиентов, которые выбирают его явно.

`npm run build` собирает Core, Generation Core (форматы данных) и Pattern Core.
Навык лендингов поставляется из `design-system_ab/apollo/skills/ab-generate-custom-landing`
через пакет данных; Figma workflow входит в совместимый runtime. Личная папка навыков
и checkout владельца в установленном Proxy не нужны. Нужны Codex, собственный вход
в Figma MCP и Desktop. Текущая страница определяется плагином; ключ файла — через
включённый private API локальной/приватной поставки. Если API недоступен, ссылка
на текущий файл принимается прямо в сообщении чата, без потери брифа. В настройках
генерации выбирается новая или существующая секция. Строка ввода доступна сразу,
«Лендинг» расположен рядом с «Новым чатом»; отдельного поля файла нет. Нормативная и визуальная проверка
остаются частью навыка; неподтверждённые результаты сохраняются как UNKNOWN, `Ready=false`.

При остановке лендинга из-за изменения окружения сохраняется bounded `outsideDiff`
с ID, свойством и значениями до/после. Baseline и строгий отказ сохраняются;
диагностика не читает текст или названия соседей. Staged Proxy проверяет
структурированный ответ текущего шага отдельно от принятого плана и выполняет
адресное исправление формата только после независимого readback.

При временной перегрузке модели совместимый Proxy показывает ожидание и выполняет
до двух повторов планирования с сохранением контекста. Stop доступен во время ожидания.
Если продолжить автоматически нельзя, чат сообщает причину перегрузки; история и
макет сохраняются для продолжения позже. Запись в Figma слепо не повторяется.

## Навык «Переназвать слои»

Во вкладке «Тулзы» карточка «Переназвать слои» анализирует текущее выделение
через выбранного в Proxy агента и показывает предложения до записи. Основные
изменения выбраны, необязательные выключены. Плагин применяет только выбранные
имена после повторной проверки исходного макета; компоненты, внутренние слои
экземпляров, автоматические имена текста, известные порты/экспорты и закрытые
области защищены. Максимум одного анализа —3000 наблюдаемых узлов и300
доступных кандидатов; для большей области нужно уменьшить выделение.
Последнее проверенное переименование можно вернуть в той же сессии плагина,
если макет с тех пор не изменился. План и результат
хранятся в памяти сессии. Версия правил и общего протокола закреплена отдельно
в `skills/figma-layer-name-hygiene/profile.json`, независимо от профиля генерации.
Анализ начинается с компактного обзора: иерархии кандидатов, имён и общего
словаря текстов. Агент может сразу вернуть план или запросить подробности
до 24 доступных слоёв за шаг. Native bridge читает их только из исходного
выделения и повторно проверяет снимок; произвольный код агента не выполняется.
Proxy ограничивает весь запуск 15 минутами и восемью шагами, включая ожидание
данных плагина. Отмена передаётся Proxy и завершает активный CLI; при потере
соединения серверный бюджет остаётся защитой от бесконечного запуска.
Новый wire-протокол 0.2.0 закреплён отдельно в `run-protocol.js`, старый
протокол и portable runtime не меняются. Правила цикла хранятся на стороне
Proxy и могут обновляться Markdown/profile-пакетом данных с совместимыми pins.
Верхний таб «Тулзы» расположен после «Спросить». Карточка открывает окно навыка поверх каталога. Анализ запускается отдельной
кнопкой «Проверить названия» после выбора области; «Остановить» отменяет ожидание
и возвращает окно к запуску. Закрытие крестиком или Escape сохраняет предложения,
выбранные изменения, результат и текущий анализ. Повторное открытие карточки
не запускает новый запрос: для этого есть отдельное действие «Новая проверка».
Предложения показаны таблицей «Было / Стало / Почему»: флажок выбирает изменение,
флажок в заголовке выбирает или снимает все предложения, включая необязательные,
и показывает частичный выбор. Необязательные предложения исходно выключены.
Нажатие прежнего имени показывает слой в Figma. Таблица прокручивается отдельно,
действия остаются у нижнего края окна. Применение и возврат имён используют
прежние проверки актуальности и результат native bridge. Во время выполнения
по центру показаны существующий маскот и одна короткая строка текущей стадии:
чтение слоёв, подбор названий, уточнение содержимого, проверка предложений,
применение или возврат имён. Подробные счётчики запуска сохранены в доступном
статусе для скринридера. Кнопки экспорта отчёта в навыке нет.
«Дизайн» и «Тулзы» используют один `AuditMascot`. Во время проверки общий

`node --test tests/design-check/layer-names-panel.test.js` проверяет переходы,

## Проверки и диагностика

Для cross-repository release-тестов полного `npm run validate` нужен checkout
Proxy по структуре из [инструкции разработчику](docs/AGENT_START_PROMPT.md).
Read-only native diagnostics включаются отдельно через `APOLLO_NATIVE_DIAGNOSTICS=1`;
для этого режима явно задаются `APOLLO_CODE_CONNECT_REPO` и
`APOLLO_CONTRACT_CATALOG_PATH` (абсолютные пути или пути относительно Apollo).
Без opt-in диагностический инструмент сообщает, что его входы недоступны;
обычная проверка, чат и генерация используют свои штатные подключения.

### Native nested instance replacement

Core0.1.23 supports the explicit `instanceReplacementDomain` opt-in for a root-owned native instance; the Editor0.2.108 authoring format is unchanged. Family/VARIANT domains remain predicates; missing source proof stays UNKNOWN. A foreign component body does not inherit the parent baseline. The Editor preserves imported replacement domains during rule edits. This support does not grant library membership, generation acceptance or runtime installation.

Apollo's runtime profile accepts version 1 of this feature and validates its binding descriptors through the same Core validator used during evaluation. Unsupported versions and malformed or unversioned descriptors are rejected before loading a contract.

An explicitly scoped replacement becomes inactive only when the published variant, captured root and reference prove the selector value. A variant without that opt-in keeps its ordinary baseline checks; an editable value or missing binding alone never establishes inactivity.

### Навык: последовательные пачки и диагностика

Большая выделенная область читается порциями и разбивается на последовательные
пачки: до 40 кандидатов и 60 000 UTF-8 байт контекста на пачку. Это целевые
размеры запросов, а не гарантия времени ответа модели. Верхняя граница области —
50 000 наблюдаемых слоёв. Прогресс показывает подготовку и завершённые пачки;
после остановки можно продолжить незавершённую пачку без повторного анализа
завершённых. Результаты сохраняются в памяти до закрытия плагина. Изменение
правил навыка между пачками требует новой проверки.

Внутренние слои INSTANCE и определения COMPONENT/COMPONENT_SET защищены от
переименования. Видимый текст экземпляра читается только как контекст.
Предложения применяются после полного анализа и выбора пользователя. Перед
действием все сохранённые факты повторно сверяются синхронно; событие nodechange
само по себе не доказывает актуальность. Проверка после записи сверяет факты,
поэтому отложенное событие собственного переименования не отключает откат.
Общая подписка documentchange и загрузка всех страниц не используются.
Граница 50 000 не является подтверждённым native-бенчмарком: большой финальный
синхронный проход может задержать интерфейс.

В подробностях запуска показаны стадия, время, provider, запрошенная модель
и безопасные события. Запрошенная модель не доказывает, какая модель исполнила
запрос. Старый Proxy без диагностики совместим; сырые ответы, тексты макета,
промпты, пути и credentials в диагностические события не включаются.
AlfaGen для этого навыка не поддержан: выберите Codex или Claude в «О прокси».


## ReGlyph в разделе «Тулзы»

«Обновить иконки» выполняет ReGlyph локально, без ИИ и Proxy. Навык доступен
при выборе iOS или Android (АБМ); обе платформы используют одну исходную
матрицу. Для Desktop и MobileWeb правила пока не подключены. Сценарии

выбор соответствий, превью и применение после подтверждения. Защищённые
иконки и нативные исключения сохраняются. Изменение платформы или канала
сбрасывает план. Источник и состав переноса: `src/skills/reglyph/ORIGIN.md`.

В существующем Apollo доступен маршрут «Дизайн → Паттерны → Проверить ProgressBar».
Он проверяет смысловой выбор Goal / Limit через текущий Apollo Proxy на localhost:3001.
После обычной проверки выделенной области используются её наблюдаемые факты и один
ленивый снимок PNG; проверка актуальности макета сохраняется. Агентский результат
показан отдельно от детерминированных нарушений. Этот пилот проверяет только два
правила выбора Goal / Limit и не означает подключения остальных паттернов.


### Выбор платформы в шапке

Desktop, MobileWeb, iOS и Android выбираются в шапке рядом с настройками. Список сгруппирован по Web и ABM; кнопка показывает название и иконку выбранной платформы. Выбор b2b / b2c / site / invest остаётся в настройках. На узком окне навигация занимает отдельную строку.

### Работа с результатом ReGlyph

Проверка закрепляется за исходной областью. Можно выделять другие объекты и
продолжать выбирать, просматривать и применять замены для ранее проверенного
фрейма. Его имя показано в результате. Перед применением плагин проверяет
актуальность исходных иконок и их принадлежность этой области. Новая проверка
использует текущее выделение; смена канала, платформы или сценария сбрасывает план.


### Семантические паттерны: Goal / Limit, Amount и кнопки

В разделе «Дизайн → Паттерны» явный запуск проверяет смысловое применение
ProgressBar Goal / Limit, Amount, Button и IconButton по выделенной области
и подключённым нормам. Для контекстных правил выбирайте блок вместе с
подписями или таблицей. Каждый компонент получает только свои правила;
вложенные служебные части не создают повторных карточек.

UI использует `component-patterns-v2` и требует совместимого кода Apollo Proxy.
Обновление только набора данных код Proxy не обновляет. При старом Proxy
проверка останавливается до агентского запуска с предложением обновить код.
Семантические результаты остаются отдельными от детерминированных нарушений.
Недостаточность контекста не означает соответствие; после изменения макета
предыдущий отчёт помечается устаревшим и переход к объекту недоступен.

### Статистика проверок и навыков

Меню Proxy «Статистика» сохраняет прежнюю историю журнала токенов. Локальные
проверки/перепроверки, проверка и замена ReGlyph, применение и отмена названий
оставляют записи с нулевым расходом. Итоги агентского анализа слоёв и паттернов
не добавляют повторно токены отдельных обращений к модели. Метаданные операций
сохраняются в ограниченной очереди Figma и удаляются после точного подтверждения
Proxy. Сохранение, отправка и повторы работают автоматически, включая восстановление
связи после перезапуска. Служебные сообщения и кнопки обслуживания очереди не
показываются на проверке и в навыках; техническое состояние остаётся в диагностике.
Это локальный журнал операций. Отчёты о результатах проверок передаются отдельным
маршрутом, описанным ниже. Запись статистики
не меняет вердикты и не блокирует работу; аварийно незавершённые локальные
операции не объявляются завершёнными по одному перезапуску Proxy.


### Выдача результатов и каталог действий

В контрактном аудите данные каждого экземпляра полностью читаются дважды: при сборе снимка и при финальной сверке перед выдачей результата. Изменение снимка останавливает выдачу устаревшего результата с сообщением о необходимости повторить проверку. Проверки состава области, версии данных и актуальности действий сохраняются.

Для TEXT со смешанной заливкой сравнение с независимым эталоном использует полные SOLID paint ranges; изменения цвета, токена и прозрачности нарушают правило, а отсутствующие или неподдержанные данные сохраняют UNKNOWN.

Неизменный скомпилированный контракт хешируется один раз за запуск. Независимые чтения импортированных источников выполняются не более чем шестью задачами одновременно; порядок диагностики и удаление временных экземпляров сохраняются. Ускорение на реальном макете требует отдельного замера после обновления плагина.

Вложенный компонент использует независимый эталон родительской сборки только после проверки объявленной привязки, ключей и соответствия двух снимков. Пути эталона переводятся в координаты ребёнка; исходный путь сохраняется в `enclosingReferencePath`. Родитель повторно оценивается только при наличии собственного ограничения цвета. Подтверждённая скрытая цель учитывается отдельно в `hiddenTargetScopes`; исходный вердикт сохраняется, а отсутствие цели или неизвестная видимость остаются пробелом проверки. Сменное содержимое Slot и INSTANCE_SWAP не становится внутренней частью родителя.

Содержимое подтверждённого native Slot не требует совпадения с библиотечным эталоном, включая Slot вложенного компонента. Диагностика проверяет native binding, тип порта и владельца по независимому эталону; сам Slot, родитель и соседние узлы сохраняют свои проверки. Исходные предупреждения и несопоставленные IDs остаются в полной диагностике, содержимое Slot — в снимке и самостоятельных проверках.

Предупреждение о несопоставленных узлах вложенного компонента использует тот же проверенный эталон родительской сборки, что и правила. Из счётчика исключаются только узлы с подтверждённым совпадением; исходный текст, IDs и producer сохраняются в `baselineDiagnostics`, подтверждённые IDs — в `ownerBaselineMatchedNodeIds`. Неизвестные и неподтверждённые узлы остаются в предупреждении. Дополнительное чтение Figma и повторная валидация эталона не выполняются.

Нативная проверка выбранной области публикует результат до загрузки каталога вариантов привязки стилей. Каталог и действия подгружаются отдельно; недоступный Proxy не отменяет готовые результаты. Поздние варианты проверяют актуальность исходного запуска и не заменяют действия более нового запроса. При настоящем прерывании чтения сохраняются доступные факты и отметка неполного покрытия; UI показывает одно пояснение без дублирования предупреждений.

При повторном запуске прежние контрактные и нативные результаты остаются видны
до готовности замены. Действия по устаревшим результатам заблокированы. Неполное
покрытие объясняется по конкретным разделам в раскрываемом блоке, включая различие
между недоступными данными и ещё не подключёнными дополнительными правилами.

Уведомление Figma `nodechange` само по себе не означает изменение макета.
Перед первым асинхронным чтением библиотечных источников проверка фиксирует
свойства и состав области; уведомления сверяются с этим состоянием. Наблюдатель
предыдущего запуска закрывается. Фактические изменения свойств, структуры или
контекста по-прежнему останавливают захват; финальная сверка сохраняется.

При `NATIVE_FACTS_CHANGED` нативная проверка сохраняет диагностический ID,
request ID, этап перепроверки, тип факта, ID узла/ресурса, причину и пути
изменившихся полей с hash до/после. Значения текста/свойств в эту диагностику
не включаются. Обычный и полный JSON-экспорт содержат `pluginBuildId` и
`nativeAudit`, включая отказ этой независимой ветки. Контрактные результаты
сами по себе не подтверждают выполнение проверок стилей и токенов.
Диагностика сохраняется и при изменении фактов после выдачи результата:
этап `observer-recheck` остаётся в JSON вместе с предыдущими находками.
Некоррелированные или расширенные диагностические пакеты отвергаются.


### Автоматическая статистика результатов

Контрактная проверка, нативные проверки и анализ паттернов создают компактные
отчёты `apollo-audit-metrics` schemaVersion=2 из уже готовых результатов.
Сохраняются происхождение, run/report ID, связь перепроверки с прежним отчётом,
версии, длительность, classifications, UNKNOWN, покрытие и доступные счётчики
компонентов. Отсутствующие сведения обозначаются null, а не нулями. Полные
snapshots, тексты макета и credentials в этот формат не входят. Имя пользователя
Figma (`currentuser`) и техническое имя JSON задают прежнюю раскладку V3:
`apollo/stats/<Имя>/<дд-мм-гггг>/<Имя>_<дата>_<время>_metrics-<origin>.json`.
Имя и локальное время окончания фиксируются до помещения в очередь; повторная
отправка их не меняет. Старые отчёты без автора используют `Unknown-User` и UTC
из `startedAt`; автора по имени компьютера не угадываем.
Анализ паттернов остаётся отдельным агентским источником.

Сначала отчёт записывается отдельным ключом clientStorage; затем автоматически
передаётся в `POST /statistics/results` Proxy. Только точное подтверждение ID и
SHA256 разрешает удалить копию в плагине. `proxy-durable` означает принятую
локальную ответственность Proxy; это ещё не подтверждение GitHub. После него
Proxy сохраняет очередь до окончательного receipt серверного publisher.
Offline, перезапуск и неверное подтверждение не превращаются в ошибку аудита.
Невалидная запись не блокирует остальные; технические ошибки остаются в логах.
Размер записи проверяется без `TextEncoder`: основной sandbox Figma не
предоставляет этот API. Регрессия проверяет сохранение и чтение очереди в
собранном native-модуле без браузерных и Node-глобалов.

Резерв плагина ограничен 1 MiB/256 записями; отдельный отчёт — 128 KiB.
Переполнение и отказ storage диагностируются; неуспевшие сохраниться записи
повторяются из памяти, её предел также фиксируется в логах. Нельзя гарантировать
сохранение несохранённой записи после аварийного закрытия при заполненном storage.
Кнопок обслуживания статистики и служебных сообщений на рабочих экранах нет.
Работа требует совместимых обновлений Apollo и Proxy; обновление данных
само по себе не устанавливает этот код. Локальная история операций/токенов
сохраняется отдельно.

### Переносимые swap-привязки и доказанное отсутствие SLOT

Core0.1.25 читает отдельные opt-in форматы: `portableSwapIdentityVersion=1` / producer0.2.109 и `nativeSlotTargetsVersion=2` / producer0.2.110. Новые bindings не меняют смысл прежних configuration pins. Для каждого сохранённого INSTANCE_SWAP, включая скрытые порты, capture получает native component key; отсутствие этого чтения сохраняет UNKNOWN. Политика main aliases сохраняет source occurrence и ближайшего владельца. Доказанное отсутствие SLOT требует согласованного независимого дерева и точной identity владельца; оно не открывает весь helper для внешнего содержимого.

Select r3 / IconView r12 требуют совместимого runtime. На retained b7 осталось70 UNKNOWN из-за5 отсутствовавших независимых nested swap references; новый owner capture должен проверить обновлённую цепочку. Это локальная техническая проверка, без публикации, установки и full Ready.

## Проверка области: восстановление и остановка (P0, 31.10.2026)

Native-проверка снимает стили после чтения опубликованных компонентов: импорт библиотеки может материализовать привязки существующих слоёв. Ресурсы стилей и переменных сначала загружаются в существующий кэш, затем findings и снимок снимаются вместе; различие до/после чтения по-прежнему требует нового захвата. PAGE/local evidence остаётся доступным при ожидании импорта. Список слоёв style scope закрепляется до раскрытия source definitions и не расширяется на другую страницу.

В консоли `[Apollo audit]` показывает начало/завершение native, интервалы материализации `phase-drift` и подтверждённые расхождения `facts-changed`. Запись содержит этап, узел/ключ, изменившиеся поля и хэши; при расхождении — последние24 события API/контрактного захвата из буфера80. Тексты, значения свойств и сырые исключения не выводятся. Интервал изменения указывает, во время какой операции оно наблюдалось, и сам по себе не доказывает действие человека. Трассировка не ставит breakpoint и не меняет результат проверки.

Один запуск закрепляет страницу, корневые узлы и платформу для контрактной и native-ветки. Смена выделения не переносит текущую проверку на другой объект. Предыдущая согласованная пара результатов остаётся видимой до готовности новой; устаревший промежуточный кандидат перечитывается.

Общий возраст проверки больше не вызывает отмену через15/20/60 секунд. Медленный Figma RPC ожидается один раз с проверкой отмены; временные отказы чтения/Proxy и подтверждённое изменение фактов вызывают безопасный повтор с паузой. RPC разных попыток имеют разные идентификаторы; ответ прежней попытки не принимается. Проверки источника, release, topology, identity, SLOT и независимого baseline сохранены. Недоступный источник/неизвестные факты не становятся PASS.

Кнопка **«Остановить»** доступна во время чтения. Остановка отменяет обе ветки и их HTTP-ожидания; подтверждение приходит после выхода контролируемой работы и очистки принадлежащих Apollo временных reference-узлов. Физически незавершаемый Figma RPC нельзя отменить API, но его позднее завершение не запускает следующие чтения и не публикует результат. Потеря подключения к интернету прекращает текущий запуск с сохранением доступных данных.

Кэшированные ответы Figma и параллельные обходы передают управление обработчику событий между порциями работы: «Остановить» не ждёт завершения всей цепочки готовых Promise. После отмены сохраняются прежние guards и очистка временных узлов. Консоль показывает начало/конец native-фаз и получение отмены (`audit-stop`), без текста макета.

Код, этап и request ID отказа сохраняются в существующих summary/full JSON и нейтральном разделе «Диагностика проверки». История ограничена первым отказом и19 последними; успешное восстановление её не стирает. Текст макета и сырой exception payload в диагностический envelope не копируются. Статистика завершения фиксируется после принятия согласованной пары либо подтверждения Stop.

Для native read ошибок диагностический envelope v2 дополнительно сохраняет API, node/resource ID, безопасный исходный code, категорию причины и hash исходного сообщения; decoder продолжает принимать v1. Одно физическое чтение опубликованного компонента учитывается один раз, даже если его отказ затрагивает несколько экземпляров: UNKNOWN каждого экземпляра остаётся в результате. Совпавшая миллисекунда не объединяет разные ошибки.

Если отдельный variant key не импортируется как опубликованный компонент, freshness пробует опубликованный набор по ключу его native-родителя. Принимается только единственный remote COMPONENT с точным variant key и подтверждённым родителем; имена и совпадение variant properties не заменяют identity. Один набор загружается один раз на запуск, исходный отказ сохраняется в истории, а отсутствие варианта остаётся UNKNOWN. Identity набора и родители старого/нового варианта входят в финальную перепроверку; действие «Обновить» повторяет тот же подтверждённый путь импорта. Это не добавляет нормативный контракт Spacers.

Финальное чтение всех контрактных captures выполняется максимум четырьмя независимыми workers, с сохранением каждого сравнения и ожиданием cleanup всех начатых операций при ошибке или Stop. В timings `verify-final-captures` показывает wall time группы; вложенные `verify-final-capture` перекрываются и не суммируются с ним. Трассировка переиспользует уже снятый снимок стилей после импорта и выводит максимум восемь подробных materialization-событий на фазу плюс полный счётчик. Обязательные snapshot, warm-up и freshness-проверки не пропускаются. Измерения на синтетических RPC не подтверждают ускорение настоящей Figma; его проверяет владелец на том же макете.

Для обработки «Остановить» чтение отдаёт управление Figma после среза работы в8мс, объединяя одновременные ожидания. Быстрые cached reads не вызывают паузу каждые32операции. `timings.readScheduling` содержит количество вызовов и суммарное ожидание чтения (`readCount`, `readWaitMs`), количество и ожидание принудительных host-turn (`hostYieldCount`, `hostYieldWaitMs`). Область `shared-reader-window` включает активность общего reader за время контрактного аудита, в том числе параллельную нативную проверку; суммы ожидания пересекающихся чтений не являются wall time и не складываются с этапами. После Stop позднее завершение RPC не меняет факты или эти счётчики.

Переход из контрактного замечания к объекту не запускает повторный захват эталонов и не создаёт временные узлы. До и после разрешения точного node ID проверяются сохранённое наблюдение сцены, актуальность отчёта, страницы и контекста; отмена и поздние ответы не могут изменить выделение. Переход не обновляет вердикт или покрытие. Полная финальная проверка аудита, проверка уведомлений об изменениях и проверки перед исправляющими действиями сохраняются.

Первичное и финальное чтение индекса устаревших стилей ожидают существующий catalog RPC с проверкой Stop/current context, без абсолютного обрыва через1с. Остальные каталожные бюджеты и проверки размера/схемы/identity сохранены. Отказ финального чтения не превращается в PASS и сохраняет собственную причину; недоступность индекса сама по себе не доказывает, что пакет данных устарел.

Producer Core0.1.25 получил необязательный `CaptureReadControl` (`guard` / `read`) для отмены на каждой native-границе. Обычные consumers без него сохраняют прежнее поведение; схема контрактов, predicate operators и нормативные правила не менялись. Подробности и consumer impact — `CC-COMPAT-AUDIT-PERFORMANCE-01` в `docs/ARCHITECTURE_BACKLOG.md`. Установка и ручной прогон в настоящей Figma выполняются владельцем.

Текущий этап общей проверки отображается одной строкой под маскотом: контрактная и native-ветки используют одно место для прогресса, ожидания и остановки. На вложенных страницах без маскота текущий этап остаётся над результатами; ошибки и диагностика сохраняются отдельно.


### Полный контекстный профиль Link

Раздел «Паттерны компонентов» использует `component-patterns-v3`: к прежним
проверкам добавлены восемь контекстных правил применения библиотечного Link.
Оценки, evidence и источник отображаются отдельно по каждому RuleID.
При проверке выбирайте область вместе с текстом и контейнером ссылки.
Неизвестное назначение, отсутствующий host или конфликт нормы дают
«Недостаточно данных». Контрактные проверки остаются отдельными.

Объявленная область берётся из настроек проверки: B2B соответствует AB-профилю,
платформа берётся из picker. Для Link принят только desktop; Mobile Web не
переключает канал в ABM. Настройки не доказывают устройство самого макета.
Контекст фиксируется для запроса; его смена прерывает прогон или помечает
предыдущий отчёт устаревшим. Требуется совместимый код Proxy V3.

Профиль охватывает экземпляры компонента Link. Гиперссылки в обычном TEXT,
фактическое открытие вкладки и точная идентичность цветовых токенов не
объявляются проверенными по скриншоту.

Native capture `apollo.progressbar-capture.v2` дополняет дерево и PNG полем
`contextEvidence` (`apollo.link-context-evidence.v1`). Для каждого наблюдаемого
узла передаются actual fills, цветовые variable bindings с ключами переменной и
коллекции, цепочкой алиасов и выбранными режимами; для текста — отдельные
сегменты с fills и hyperlinks. Имена токенов и совпадение RGB не заменяют ключи.
Public component properties, componentPropertyReferences и узлы SLOT сохраняют
фактический контекст вложения: Caption не становится action-слотом по имени слоя.
Prototype reactions и annotations описывают намерение в макете; они не доказывают
работоспособность frontend или согласование исключения дизайн-системой.

Отсутствующее значение, неподдерживаемое свойство и отказ чтения различаются
явными статусами. Поле включено в fingerprint и повторное native чтение до
запуска агента, после ответа и при навигации к результату. Изменение binding,
алиаса, режима, слота, prototype или annotation делает capture устаревшим;
shared-resource proof сохраняется. UI принимает прежний capture v1 и новый v2;
для v2 нужен совместимый Proxy. Выбирайте область с контейнером ссылки:
контекст за границей выбранного дерева не добавляется автоматически.

### Saved pattern finding navigation

After the final native proof completes, pattern findings remain focusable when the selection is cleared or changed. Actual captured-node edits, page changes and audit-context changes still make the report stale. A completed read-only finding retains its original capture root and every shared-resource freshness proof for navigation. Pending checks retain the original selection and shared-source freshness guards.

В разделе «Генерация» список сценариев загружается из установленных навыков Proxy.
Выбор фиксируется при создании чата; новый сценарий начинается через «Новый чат».
Старый совместимый Proxy без реестра сохраняет прежний сценарий лендинга.

Служебный каталог контрактов читает все записи manifest и dependency sources без
фиксированного предела количества. Ограничение можно передать явно через
`maxContracts`; проверки путей, хешей, размеров файлов, идентичности и compiled projection сохраняются.

### Каталожные правила стилей и токенов V3

Native audit использует `/v1/style-token-catalog/audit-policy` Proxy: ключи применённых стилей и COLOR-переменных проверяются по каталогам пакета знаний. Совпадение имени или RGB не подтверждает принадлежность каталогу. Недоступные ресурсы и неоднозначные типы остаются UNKNOWN. Исключения V3 ограничены заливками внутри подтверждённых Icons/Logotypes и заданным контекстом типографики Status; эффекты и остальные свойства продолжают проверяться.

Индекс повторно проверяется перед выдачей результата и после scoped recheck. Изменение пакета требует нового захвата; отсутствие индекса сохраняет native-находки и неполное покрытие. Нужны совместимые код Proxy и пакет с reference manifest, auditPolicies и индексами Icons/Logotypes. Старый пакет не объявляется полностью проверенным.

Локальность компонентов по-прежнему определяется native `main.remote`, а не именем или отсутствием в каталоге. Отказ импорта внешнего компонента не превращает его в локальный.


В source-профиле лендинга0.3.2 Proxy хранит полный план и pinned чтения, резервирует
шаги для сборки и допускает отдельное техническое уточнение активной секции. Native
структура, отчёт агента и просмотр изображений учитываются раздельно; неполная
проверка сохраняет `needs-verification` и `Ready=false`. Требуется совместимая
поставка плагина/runtime/data; source change сам её не устанавливает.
Подробнее: [лендинг](docs/LANDING.md).

Локальный пилот каталогов TitleView расширен на Desktop/MobileWeb: 16 вариантов,
единая матрица r4 и доказанные прямые BOOLEAN→visible настройки. Дополнение ещё
не опубликовано; известные Skeleton/mixed пробелы остаются явными. Источник raw
не заменён: оба представления уже были в нём. См. [границы пилота](docs/CATALOG_AUDIT_PILOT.md).

TitleView pilot: сбор ссылок для каталожной проверки отделён от ограниченного
сборщика подписей UI. Контракт r5 использует существующее строгое сопоставление
локальных materializations одного library key; неподтверждённые источники и
настроенные вложенные эталоны сохраняют UNKNOWN. Установку и полевую приёмку
обновления выполняет владелец.

Apollo0.4.2 / Proxy1.4.17: контракт TitleView r5 исполняет согласование двух
видимых Type и Desktop-запрет Accent для доказанных Button occurrences.
Новый read-only usage opt-in не назначает вложенным слоям визуальный baseline.
Требуются совместимые приложение и свежий пакет данных; старый источник с

Локальная Apollo0.4.3 разделяет сопоставление эталона и чтение правил TitleView:
недоступный ресурс или соседняя ветка не отменяют доказанные сравнения и
проверки Type/View. Все локальные ID одного подтверждённого library key
сохраняются как aliases; независимый каталог не получает произвольно выбранный
ID экземпляра. Отсутствующие факты остаются UNKNOWN, покрытие — неполным.
Используются прежний загрузчик структур V3, нормализация библиотечных ключей и
существующий Predicate Engine; второго интерпретатора контрактов нет.
Режим проверки пилота — «Подключить каталоги». Контракт r5 и данные 1.4.17
не изменены. Новая сборка подготовлена локально, полевая приёмка владельцем впереди.


Apollo0.4.4 (локально): при недоступном независимом каталоге удаляется
authoring self-baseline сборщика; факты `baseline.effective` остаются UNKNOWN.
Режимы нескольких source aliases одной опубликованной коллекции проецируются
по подтверждённой native mode domain. Несовместимые режимы сохраняют неизвестным
visual baseline только соответствующего узла, без подстановки фактических

зависимостей; их самостоятельные native-каталоги ещё необходимы для полного

### Аудит выбранной области по DS AI HUB

В «Тулзы» → «Проверка по DS AI HUB» доступен отдельный read-only исполнитель
`ab-audit-figma`. Нужны совместимые Proxy и пакет данных с этим навыком.
Выделите область, откройте инструмент и нажмите «Проверить область».

Пилот `ab-audit-figma` 0.4.3 сравнивает TitleView и Button с выбранными вариантами
существующих Athena-каталогов из установленного пакета. Плагин собирает технические
отличия «узел + поле», Proxy проверяет происхождение эталона, а агент оценивает
допустимость по нормам DS AI HUB. Отличие само по себе не считается нарушением.
Каталожные значения, native-факты и цитаты Hub хранятся раздельно; недоступные
поля и неподтверждённое сопоставление остаются явными пробелами. Детерминированный
тракт V3 не меняется. Для пилота нужен согласованный wire v3 в Apollo/Proxy и
обновлённый навык; новые выгрузки компонентов не требуются.

В исходниках подготовлено табличное отображение результатов: статус, правило и
слой, фактическое значение, требование и исправление. Объяснение, исходный
документ и дословная цитата раскрываются в строке. Статусы и самостоятельное
использование компонентов показаны отдельной таблицей. Сохранены фильтры,
предварительные результаты, пометка устаревания, переход к слою и JSON-экспорт;
на узком экране таблица прокручивается с клавиатуры. Само изменение UI не
устраняет пропуски применимых правил в плане аудита. Доработка подготовлена
для локальной сборки 0.4.11.

Новый host Proxy отдельно учитывает обнаруженные overrides как обязательные
пункты «узел + поле». Проверка размера родителя не закрывает изменение
типографики вложенного текста. Пропущенные пункты остаются NOT_CHECKED,
недоступные перечни — UNKNOWN; метаданные изменений не заменяют доказательства
и не предоставляют права чтения. Покрытие изменений показывается отдельно от
покрытия правил и сохраняется в JSON. Навык и логика host поставляются
с совместимыми Proxy и данными.

`src/figma-audit/native.js` предоставляет фиксированные операции чтения;
произвольный JavaScript модели не выполняется. Переход к найденному слою
меняет только выделение и viewport по нажатию пользователя. Итоговый JSON
содержит матрицу правил, факты, источники с хешами и диапазонами, пробелы и
реальный usage CLI по фазам. Coverage описывает объявленный набор правил,
не полноту всех знаний Hub. Перед показом результата перечитываются
использованные actual/source/style/variable факты. Изменение макета после
проверки помечает сохранённый отчёт как устаревший.

В этом пилоте доступны только свойства выбранного статического состояния;
скрытые ветви, недоступные remote masters, поведение и другие viewport
остаются явными ограничениями. Нормы компонентов не зашиты в плагин.

Протокол проверки отдельно объявляет ближайших родителей как context-only:
их layout/оформление можно прочитать, но соседи, предки и новые цели аудита
не допускаются. Поиск Hub сопоставляет `TitleView` и `title-view`. Совместимость
Apollo/Proxy проверяется до capture и CLI. Пилот 0.4.3 требует wire v3;
несогласованные наборы отказывают до чтения и вызова модели. Контрактный пилот
не является запасным путём действующей проверки V3.

В исходниках UI показывает фактическую операцию и контекст последних действий.
Готовые группы выводов появляются как предварительные: обновление того же ID
не увеличивает счётчик, неполученные строки остаются «Не проверено». Итоговый
набор обязан покрыть весь объявленный план и пройти перепроверку Figma.
Непокрытые экземпляры перечисляются отдельно; это не гарантия всех правил Hub.
В исходниках исправлены отмена по requestId до получения runId, ограниченное
хранение завершённых запусков и привязка typed requiredFields к конкретным
прочитанным полям. Недоступный факт оставляет UNKNOWN только у зависимого вывода.
Отмена и история сохраняются на диске; старый запрос не вызывает модель повторно.
Это не доказывает полноту списка фактов или правильную интерпретацию нормы моделью.
Audit client/host дополнительно сверяют request-id-v1, native-fields-v1 и
версию профиля до вызова модели. Сборка, публикация и установка — отдельные
действия; локальные исходники сами не обновляют установленный плагин или Proxy.

### Чтение существующих raw-каталогов, локальная 0.4.5

TitleView и 11 вложенных контрактов используют существующие Athena `structure`
и `variantStructures` через V3 reader Proxy. Дополнительный native JSON-блок
и новая выгрузка не нужны. Корректное сопоставление ветви даёт независимый
baseline; смена варианта того же семейства даёт только типизированную настройку
для правил применения. Неоднозначный узел не подбирается по порядку или по
значению проверяемого свойства. Сбой одного факта не отменяет другие проверки.
Текущая схема и ограничения заменяют прежнее требование native-enrichment: см.
[каталожный пилот](docs/CATALOG_AUDIT_PILOT.md). Доставка и ручная приёмка отдельно.

Отдельный скалярный baseline может быть доказан без выбора единственного узла:
raw reader использует значение, общее всем кандидатам полного независимого
сопоставления, включая скрытые siblings. Пока поддержаны literal padding и
известная применимость layout-свойств; привязка padding к токену сохраняет UNKNOWN.
Остальные поля и целые контейнеры остаются UNKNOWN. Импортированный `knownFacts`
не является доказательством: core очищает его и строит заново. Это source candidate
для отдельной приёмки; выпущенные Apollo0.4.7 / Proxy1.4.22 не пересобирались.

В исходниках подготовлен общий dropdown истории лендингов. Иконка корзины в
строке чата открывает подтверждение удаления; текущий чат и несохранённый бриф
сохраняются при удалении другой строки. Макет Figma и диагностическая копия
сохраняются, повтор после потерянного ответа безопасен. Работающий чат сначала
нужно остановить. Изменение подготовлено для локальной сборки 0.4.11; подробности:
[удаление чата](docs/LANDING.md#удаление-чата-из-истории).

В исходниках Proxy результат записи MCP связывает операцию, источник, этап,
секцию и область записи. Новый формат проверяется полностью; прежний формат
сохранённых результатов остаётся совместимым. Фактические ID после вставки
подтверждаются независимым чтением. Разрешённая замена default SLOT выполняется
одним вызовом: добавление, проверка замены, свежая pristine-проверка и удаление
доказанно нетронутого default. Проверки сохранены в компактном техническом коде;
после загрузки шрифтов повторно проверяются owner/lease. Это доработка
существующего workflow, требующая совместимой поставки Proxy и данных.

### Интерфейс V3 в подготовке локальной сборки 0.4.11

Допустимые настройки скрыты из списка нарушений и сохранены в диагностическом
JSON. Статусы update/changed показываются в «Пора менять» как предупреждения;
цвет маскота учитывает все разделы, включая Базу. Доступны проверенное действие
«Выбрать Alfa Sans», полные пары замены компонентов и компактный общий список
исправлений. Уведомления появляются поверх интерфейса, параметры области
блокируются во время проверки. Фокусировка по сохранённому ID исходной страницы
доступна для устаревшего отчёта; исправления требуют свежих доказательств.
JSON сохраняет ограниченную диагностику инвалидации: стадию, причину, слой и
поля. Причина прежних незафиксированных отказов не считается установленной.

### Индексы статусов в ab-audit-figma 0.4.0 (source candidate)

Аудит читает закреплённые deprecated/scheduled/parts индексы отдельно от правил Hub.
Scheduled выводится предупреждением. Parts — ошибкой только при положительном
подтверждении самостоятельного использования; неполная вложенность — UNKNOWN.
Счётчики, покрытие и provenance находятся в отдельном catalogLifecycle блоке
предварительного и итогового отчёта/JSON. Source candidate требует совместимого
нового Proxy, skill-пакета и native; публикация и ручная приёмка выполняются отдельно.
